# v2.0 decisions log

One line of rationale each. Made autonomously on 2026-09-12 per the mission brief.

| # | Decision | Rationale |
|---|---|---|
| 1 | Eval framework: custom Groq judge (not Ragas/DeepEval) | Ragas 0.4.3 requires `langchain` 1.x, incompatible with pinned `langchain-core==0.3.86`; older Ragas and DeepEval 4.x drag large dependency trees against a pinned set we must not upgrade. The three metric definitions fit in ~150 lines using the existing tiered router. Decided in <10 min via `pip install --dry-run`. |
| 2 | CI runs against a `pgvector/pgvector:pg16` service container seeded with `data/sample.txt` | Hermetic and free; the Supabase free project pauses on idle (it is paused right now), so CI must not depend on it. |
| 3 | Retrieval MCP server accepts an optional precomputed `query_embedding` | Render free tier is 512 MB; a second in-process copy of bge-small (~230 MB) in the subprocess risks OOM. The orchestrator passes the vector; external callers omit it and the server embeds lazily. |
| 4 | Per-call stdio MCP sessions (adapter default) rather than persistent sessions | Simplest lifecycle; same behavior the utils server already has in prod. Persistent sessions are a measured follow-up if Render latency is poor. |
| 5 | Per-branch corrective gate inside `retrieval_worker` (doc → web per sub-query) | Makes the roadmap's own example ("X in doc A and Y on the web") actually produce mixed doc+web grounding in parallel; the global gate value is untouched. |
| 6 | Tool errors degrade to "no chunks" → web fallback instead of failing the request | The live demo must keep answering web questions while the DB is paused; also the HLD's "tool error degrades gracefully" requirement. |
| 7 | Typecheck with pyright (basic) rather than mypy | Faster, better inference on untyped code; pip-installable (bundles node via nodeenv). |
| 8 | Fan-out cap 3, relevance threshold untouched | Standing decisions from the mission brief. |
| 9 | Persistent (keep-alive) stdio session for `groundscope-retrieval`; per-call sessions for web/utils | Review finding: per-call spawns import numpy+psycopg (~70 MB, seconds on 0.1 CPU) and a 3-way fan-out would spawn three at once. One long-lived retrieval child keeps fan-out concurrent and cheap; web/utils are rare and light, so per-call is fine. Flagged in mcp.json as `"keepalive": true` (stripped before the adapter sees it). |
| 10 | Judge = single combined call per case on `llama-3.1-8b-instant` (configurable `EVAL_JUDGE_MODEL`), paced | Groq free tier caps 70B at ~100K tokens/day; the agent already spends that. A separate, larger-budget judge model also avoids self-preference. |
| 11 | CI corpus = `data/corpus/*.txt` (fictional companies, ~15 chunks) seeded by `scripts/seed.py` | Review finding: `sample.txt` is one chunk, too thin for 15+ grounded cases and for context precision. Fictional facts keep `expect_grounded` meaningful (the web cannot answer them). |
| 12 | Trace never shows raw exception text from tools; only the exception type | psycopg errors include the DB host and user; the panel is public. Full text goes to the server log. |
| 13 | Trace panel builds DOM with `textContent` (no `innerHTML` for tool output or link titles) | Stored-XSS risk once summaries carry tool output and Tavily titles. In blast radius, fixed with the lane renderer. |
| 14 | Per-branch tool timeout (`tool_timeout_s`, default 60) | One hung MCP call would hang the whole fan-out and the SSE stream. |
| 15 | Execution mode: tightly coupled graph/bus tasks inline (executing-plans); isolated tasks (UI lanes, golden set, CI yaml) via subagents | Subagents lose the langgraph 0.2.39 / mcp adapter details that the review surfaced; the isolated pieces do not need them. |
| 16 | Models: primary `openai/gpt-oss-120b`, fallback `openai/gpt-oss-20b`, judge `openai/gpt-oss-20b` | Discovered 2026-09-12: Groq returns 404 for `llama-3.3-70b-versatile` and `llama-3.1-8b-instant` (retired). The live site's LLM calls were therefore already failing. gpt-oss models are on the free tier; the judge is a different model than the agent to reduce self-preference. |
| 17 | Eval: `metadata` cases skip the LLM judge; deterministic checks still apply | The metadata route retrieves no contexts, so faithfulness/precision are undefined there; scoring them 0 would punish a correct deterministic answer. |
| 18 | `web_search` is never advertised to the planner as an action tool | The first real eval run showed the planner sending plain factual questions to the ReAct worker (empty answers, no grounding) because web_search looked like an action; the knowledge path already runs web fallback deterministically. |
| 19 | Fan-out dedupe keys on chunk text, citations dedupe on page | Every chunk of a one-page document shares the label `file p.1`; keying only on the label dropped the answer-bearing chunk (found by the first eval run). |
| 20 | Keyword leg of hybrid retrieval ORs the query terms (`to_tsquery`, ranked by `ts_rank`) | `plainto_tsquery` ANDs every word, so a full question with one absent word returned no keyword hits and fusion silently degraded to dense-only; the evals missed three Meridian facts because of it. The relevance gate (best dense distance, threshold value) is untouched. |
| 21 | Eval `must_contain` compares normalized text (NFKC, Unicode dashes/spaces folded, markdown emphasis stripped) | gpt-oss emits U+2011 hyphens and U+202F spaces; a byte-level check failed correct answers. |
| 22 | Eval judge = `qwen/qwen3.8-27b` on Groq | Groq caps each model at ~200K tokens/day (rolling) on the free tier; the judge on gpt-oss-20b exhausted the bucket the agent's fallback also uses. Qwen has its own bucket and is a different model family from the agent (less self-preference). |
| 23 | Gemini (`gemini-3.5-flash-lite` via the OpenAI-compatible endpoint) as the third failover tier and the eval judge whenever `GEMINI_API_KEY` is set | Separate vendor and quota from Groq: the judge can never share the agent's exhausted daily bucket, and the agent keeps answering when both Groq tiers are capped. `gemini-2.5-*` are retired for new users; `gemini-3.8-flash` returned 503 (high demand) during the probe, so the lite model is the reliable pick. |
| 24 | Context-precision threshold calibrated to 0.25 (initial guess was 0.60) | Measured baseline on the first run where every deterministic check passed (2026-09-12, run 7): faithfulness 0.88, answer relevance 0.94, context precision 0.35, checks 18/18. Each branch retrieves k=6 chunks from an 11-chunk corpus and the judge counts one or two as relevant, so ~0.35 is what a healthy system scores; 0.60 was never reachable. 0.25 still catches a retrieval regression (dense-only fusion scored ~0.15). Faithfulness 0.85 and relevance 0.70 stand. |
| 25 | Per-minute 429s are waited out on the same tier (hint <= 30 s, at most twice); per-day 429s fail over at once; the Groq judge (`EVAL_JUDGE_MODEL`) is an explicit second judge when Gemini is rate-limited, with the judging model recorded per case | Groq's free tier caps each model at 8K tokens/minute and 200K tokens/day (rolling). Failing over on every per-minute burst spilled the agent to Gemini all day (2026-09-12) until its 500 requests/day were gone; then main run 34707733909 had 11 of 18 cases with no model and 3 with no judge, while the same code had passed 17/18 an hour earlier. The tier failures were not logged, which hid this; they are now. The judge fallback is not silent: it is a configured judge from a different family than the agent, and `judge_model_used` names it. |
| 26 | Demo corpus = the Bhagavad-Gita in Sir Edwin Arnold's 1885 translation (public domain, Gutenberg #2388), one text file with a form feed between chapters so `p.N` is chapter N; not added to the golden set | The user's own Gita references are copyrighted translations (Sargeant, Tapasyananda, Boray) and the site republishes snippets, so a public-domain text is the safe seed. The eval corpus stays fictional because the model knows the Gita by heart: a Gita case could pass `must_contain` from memory without grounding. |
| 27 | The Sources block lists only the citations the answer references (label, or URL for web results); all retrieved sources are kept when the answer cites none | Found on the live site 2026-09-12: a resume question also retrieved a Zephyr chunk inside the gate and the Sources block listed it, which reads as a wrong citation. Page labels match whole numbers so `p.1` never matches `p.10`. |
| 28 | The trace and the answer payload carry the model that answered; eval rows carry `agent_model_used` | Three tiers and daily quotas: without it nobody can tell whether Groq or Gemini wrote an answer or scored a case. |
| 29 | gpt-oss models are called with `reasoning_effort: low` (via `extra_body`, both clients); an empty completion cut by length is retried once with double `max_tokens`, then counts as a failed tier | Live Gita question 2026-09-12: six verse chunks, 700-token synthesis, gpt-oss spent it all on hidden reasoning and returned empty content, which the UI showed as a blank answer with six citations. Low effort keeps the budget for the answer and also cuts the daily token spend; the retry-then-fail-over rule means a blank can never reach a visitor as an answer. |
| 30 | Corpus packs (`data/packs/<pack>`): a TOML manifest plus canonical Markdown documents, one per source edition, each unit tagged `<!-- ref: text.unit -->` with `### Part` blocks; the PDF is never the indexed object | A PDF is a rendering. Indexing it by 400-word windows throws away the structure (verse, commentator, translator) that scripture questions are actually about ("what does Shankara say on Isha 9"). One file per source keeps provenance, language and license separable; units join on `ref`. |
| 31 | Pack records are chunked at paragraph boundaries within a unit (≤ ~350 words), embedded with a contextual header, and stored with `metadata jsonb`; citations use the unit label | A chunk never straddles two verses, so a citation is exact. The header ("Isha Upanishad with Shankara's commentary | Verse 2 | Commentary | Shankara, tr. Gambhirananda") fixes retrieval misses on short chunks and lets BM25 match on verse and commentator names. Unit labels replace `file p.N` only when metadata is present, so uploads are unchanged. |
| 32 | Sanskrit mantras and bhashya come from a clean digital encoding (sanskritdocuments.org), never from OCR; English from the PDF text layer, footnotes read from page images of the printed scan | OCR renders Devanagari as garbage (both archive.org files). The re-typeset English file had usable text but had dropped every footnote, and its wording differs slightly from the older printing, so the edition is recorded in the front matter and footnotes carry an A.G. marker where Gambhirananda cites Ānandagiri. |
| 33 | Gambhirananda's translation stays in a private/local pack; a public deployment must use public-domain translations | The English translation is Advaita Ashrama's copyright. The user accepted this for personal study; the site is public, so the pack manifest records the license per file and the seed target is chosen per deployment. |
| 34 | Agent stack moved to LangGraph 1.2: `langgraph` 1.2.12, `langchain-core` 1.6.6, `langchain-openai` 1.6.7, `langchain-mcp-adapters` 0.3.2, `openai` 3.24.0. Supersedes the "pinned set we must not upgrade" in row 1 (numbers 30 to 33 are taken by unmerged corpus-pack work) | v2.1 needs `interrupt()` and the Postgres checkpointer, which 0.2.39 does not ship. The family has to move together: LangGraph 1.x requires `langchain-core` >= 1.4.7 and `langchain-openai` 1.6 requires `openai` >= 2.45; `mcp` stays on 1.27.2 because the adapters require `mcp` < 2, and `langsmith` 0.8.9 already satisfies the new range. The one behaviour change was in the MCP adapters, which now return content blocks; `toolbus.tool_text` reads their text for the bus and the ReAct loop. `langgraph-checkpoint-postgres` 3.1.2 resolves against these pins and is added when v2.1 uses it. Row 1's custom judge stays: it is about 150 lines, runs on the free tiers, and Ragas would add a dependency tree for the same three metrics. |
| 35 | Pack texts and build output are not tracked: `data/packs/*/texts/` and `data/packs/*/build/` are gitignored, and all four Isha files stay together on the author's machine. Tests that need them skip when the folder is absent; a synthetic two-verse pack in `tests/conftest.py` covers the build and seed path in CI | This repository is public. Gambhirananda's translation is Advaita Ashrama's copyright and the Sanskrit bhashya encoding carries a no-repost notice (row 33), so publishing the folder would republish both. The author asked for the pack not to be split into a tracked public-domain half and an untracked half; keeping it whole and local is the option that publishes nothing. The skip is by design, not a missing CI dependency, which is why it is a skip and not a failure. |
